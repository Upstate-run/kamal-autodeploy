# v1 scope and limits

Kamal Autodeploy v1.0.0 provides reviewed GitHub Actions workflows for deploying
changed Kamal units. It is an independent project, not affiliated with Kamal.

## Included

- Discovery, readiness checks, reviewed configuration and workflow generation.
- Changed-unit selection, ordered prerequisites and reconciliation against the
  newest eligible green commit within the latest 25 first-parent commits.
- Required CI checks, serialized deployment, deployment guards, dedicated SSH
  keys and pinned host keys. Review generated workflows and environment rules.
- Manual deployment dispatch, rollback dispatch and read-only PR impact previews.
  New configurations start in manual mode; automatic activation is explicit.
- Optional Tailscale OIDC connectivity, with explicit tags and network policy.
- A whitespace-delimited `[skip-deploy]` token on a landed commit holds automatic
  deployment at that boundary until a subsequent unmarked commit passes required
  CI. An explicit manual deployment overrides the hold for its selected unit;
  green CI is still required. Raw PR titles, descriptions and labels do not
  control this hold.

## Boundaries

The selection window is bounded: this is not an unbounded queue of every green
commit. Manual dispatch reconciles pending units and prerequisites, so it can
include more than the unit an operator first had in mind. CI remains required.
A pending check requires another manual dispatch after it completes.

PR previews apply the base branch's reviewed rules to the PR's impact. They do
not promise the final release diff or authorize a deployment. Rules changed in
that PR take effect only after landing and review of the resulting workflow.

Kamal remains responsible for the deployment itself. Operators own application
health checks, migrations, credentials, backups, rollback safety and host access.
Rollback cannot reverse database changes or external side effects. Test those
procedures for each application before enabling automatic activation.

Upstate is optional. Core deployment works with it disabled. Hosted Upstate
onboarding and integration are outside v1; proposed integration work is not part
of this release. Existing optional CLI hooks do not imply hosted integration.

v1 has been exercised against multiple repositories and deployment units. That
acceptance evidence does not guarantee every Kamal layout, private network or
application migration strategy. Review discovery output and run doctor and a
controlled deployment for each newly configured application.
